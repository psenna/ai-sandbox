> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the k8s-native execution-model end-to-end test surface (kind-based, real kubelet) plus the small implementation seam it needs (`Destroyed.Pods` marker + a k8s-native engine teardown + fake-CLI `services`/`exec` directives), then verify it green against a local kind cluster.

**Architecture:** Plan 1 shipped the `ServiceSet` CRD + reconciler; Plan 2 shipped the agent-facing control API (`/v1/services`, `/v1/exec`), `services.yaml` parsing, admission validation, compose renderer, and the `#2` name-collision fix. Plan 3 closes the loop with the real-kubelet surface envtest cannot cover: lifecycle (k8s-native *implemented* posture), network isolation (Restricted/Open egress against a broker), control-plane isolation (a runtime pod cannot reach the agent's loopback control API), services (a declared service reachable via Service DNS + version-switch recreates only the changed pod), compose (the real `sandboxctl services compose` binary path), and snapshot/teardown (`Destroyed.Pods`). Two implementation pieces land here because they are test-only seams the design §6 calls out: the `Destroyed.Pods` marker field (back-compatible with `Destroyed.Containers`) and a k8s-native `EngineTeardown` that populates it.

**Tech Stack:** Go 1.24, Ginkgo v2 / Gomega, controller-runtime, kind (v0.30.0, node `kindest/node:v1.34.0`), kubectl v1.34.0, the existing e2e harness (`operator/test/e2e`, a separate go module with `replace … => ../..`).

## Global Constraints

- The e2e module is at `operator/test/e2e` — a SEPARATE Go module (`go.mod` with `replace github.com/psenna/ai-sandbox/operator => ../..`). Local compile-verify is `go test -c -o /dev/null ./...` (NOT `go build ./...`, which fails because `var h *Harness` lives in `suite_test.go` and is referenced by non-test `metrics.go`).
- Local run path: `IN_CONTAINER=1 SHARED_DIR=/tmp/ai-sandbox-e2e make e2e-up` then `IN_CONTAINER=1 SHARED_DIR=/tmp/ai-sandbox-e2e make e2e-run` then `… make e2e-down`. `IN_CONTAINER=1` makes the Makefile's docker-wrappers host-native. The cluster is named `ai-sandbox-e2e`.
- Security invariants (end-to-end, must hold): the agent container holds NO Kubernetes credential (automount disabled at SA + pod; token projected into the `sandboxctl` sidecar only); the control API is loopback-only (`127.0.0.1:9099`, never a Service); no hostPath/privileged/devices; data PVCs RWO; RBAC scoped.
- Pod labels set by the ServiceSetReconciler: `ai-sandbox.io/serviceset=<envName>`, `ai-sandbox.io/entry=<entry-name>`, `ai-sandbox.io/kind=<service|runtime>`. The ServiceSet CR is named exactly `<envName>` (the sidecar upserts by name = `cfg.Environment`). ServiceSet status `Entries[].Name` carries each entry name, and each Pod is named exactly its entry name — so pod names are derivable from the ServiceSet (no `pods list` RBAC needed).
- Container names in the rendered agent pod: `agent` (`render.AgentContainerName`), `sandboxctl` (`render.SidecarContainerName`, holds the `sandboxctl` binary at `/sandboxctl` and the loopback control API), `restore` (one-shot wake init).
- `Destroyed.Pods` is a NEW JSON field on the teardown marker, kept BACK-COMPATIBLE with the existing `Destroyed.Containers` (both stay in the struct; k8s-native populates `Pods`, podman would populate `Containers`). The existing `Destroyed.Containers` field, `RenderMarkdown`, and all existing marker tests MUST stay green.
- The k8s-native engine teardown is **list-only**: it reads the ServiceSet, enumerates entry names (= pod names), and reports them in `Destroyed.Pods`. It does NOT delete pods or the ServiceSet. Rationale (load-bearing, from the code): service data PVCs are owned by the ServiceSet (`ownerRef(ss)` in `serviceset_controller.go:364`), so deleting the ServiceSet would garbage-collect the data PVCs (data loss across freeze/wake); deleting only the pods triggers a reconcile storm (the ServiceSetReconciler recreates them). RWO co-mount lets the snapshot Job archive the workspace PVC on the same node without evicting pods, and the agent quiesces (sandbox-wait) before freeze, so writers are idle. A follow-up issue tracks a suspend-aware teardown that stops writers without storm/data-loss; this plan ships the faithful, safe minimum. No new RBAC is required for the teardown (it reads the ServiceSet via `servicesets get`, already granted).

```go
type TeardownReport struct {
	Engine     string   // "none" | "rootless-podman" | "k8s-native"
	Containers []string // podman: stopped+removed, sorted, deterministic
	Pods       []string // k8s-native: ServiceSet pods present at freeze, sorted
	Note       string   // human-readable, surfaced in RESUME.md
}

// NewEngineTeardown selects the EngineTeardown for engineType. The k8s-native
// teardown reads the env's ServiceSet (named envName in namespace) to enumerate
// its pods, so it needs the in-cluster client + the env identity; the other
// engines ignore them.
func NewEngineTeardown(engineType string, c client.Client, namespace, envName string) EngineTeardown {
	switch engineType {
	case "", "none":
		return noopEngineTeardown{}
	case "rootless-podman":
		return notImplementedEngineTeardown{engine: "rootless-podman", issue: 24}
	case "k8s-native":
		return k8sNativeEngineTeardown{c: c, namespace: namespace, envName: envName}
	default:
		return notImplementedEngineTeardown{engine: engineType, issue: 24}
	}
}

// k8sNativeEngineTeardown is a LIST-ONLY teardown: it reads the env's ServiceSet
// and reports its entries' pod names (pod name == entry name) in TeardownReport.
// Pods. It does NOT delete the ServiceSet or its pods. Rationale: service data
// PVCs are owned by the ServiceSet (serviceset_controller.go's ownerRef), so
// deleting the ServiceSet would GC the data PVCs (data loss across freeze/wake);
// deleting only pods triggers a ServiceSetReconciler recreate storm. RWO co-mount
// lets the snapshot Job archive the workspace PVC without evicting pods, and the
// agent quiesces (sandbox-wait) before freeze. A follow-up tracks a suspend-aware
// teardown that stops writers without storm/data-loss.
type k8sNativeEngineTeardown struct {
	c         client.Client
	namespace string
	envName   string
}

func (e k8sNativeEngineTeardown) Teardown(ctx context.Context) (TeardownReport, error) {
	var ss sandboxv1alpha1.ServiceSet
	if err := e.c.Get(ctx, client.ObjectKey{Name: e.envName, Namespace: e.namespace}, &ss); err != nil {
		if apierrors.IsNotFound(err) {
			return TeardownReport{
				Engine: "k8s-native",
				Note:   "k8s-native: no ServiceSet applied (no pods to tear down)",
			}, nil
		}
		return TeardownReport{}, fmt.Errorf("reading ServiceSet %s/%s: %w", e.namespace, e.envName, err)
	}
	names := make([]string, 0, len(ss.Status.Entries))
	for _, entry := range ss.Status.Entries {
		names = append(names, entry.Name)
	}
	sort.Strings(names)
	return TeardownReport{
		Engine: "k8s-native",
		Pods:   names,
		Note:   fmt.Sprintf("k8s-native: %d pod(s) present at freeze (list-only; reconciler-managed; data PVCs retained)", len(names)),
	}, nil
}
```

Header doc additions:

```
#   SCRIPT:sandbox-services-apply <json>  POST $SIDECAR/v1/services, must 2xx   (exit 40)
#   SCRIPT:sandbox-exec <runtime> <cmd...> POST $SIDECAR/v1/exec; expect 2xx + exitCode 0
#                                          (exit 41 on API non-2xx or exitCode!=0)
#   SCRIPT:sandbox-exec-expect-fail <runtime> <cmd...> same exec; expect 2xx + exitCode!=0
#                                          (exit 42 if API non-2xx OR exitCode==0)
```

`case` arms (the `sandbox-exec` family parses the runtime token then passes the REST of the line as the command, splitting on spaces — matching how the real `sandboxctl exec <runtime> -- <cmd...>` takes a command):

```bash
	"SCRIPT:sandbox-services-apply "*)
		payload="${line#SCRIPT:sandbox-services-apply }"
		code="$(curl -sS -o /dev/null -w '%{http_code}' --max-time 10 -X POST "$SIDECAR/v1/services" -H 'Content-Type: application/json' -d "$payload")"
		case "$code" in
		2??) ;;
		*)
			echo "claude: sandbox-services-apply got HTTP $code, want 2xx" >&2
			exit 40
			;;
		esac
		;;
	"SCRIPT:sandbox-exec "*)
		rest="${line#SCRIPT:sandbox-exec }"
		runtime="${rest%% *}"
		cmdline="${rest#* }"
		# Build the JSON command array by quoting each whitespace-split token.
		cmdjson="$(printf '%s' "$cmdline" | awk '{for(i=1;i<=NF;i++){printf "\"%s\"%s",$i,(i<NF?",":"")}}')"
		payload="$(printf '{"runtime":"%s","command":[%s]}' "$runtime" "$cmdjson")"
		resp="$(curl -sS --max-time 30 -X POST "$SIDECAR/v1/exec" -H 'Content-Type: application/json' -d "$payload")"
		rc=$?
		if [ "$rc" -ne 0 ]; then
			echo "claude: sandbox-exec curl failed (rc=$rc)" >&2
			exit 41
		fi
		# exitCode is the command's exit; 0 = success. jq-free parse via sed.
		ec="$(printf '%s' "$resp" | sed -n 's/.*"exitCode":\(-\?[0-9]\+\).*/\1/p')"
		[ -n "$ec" ] || ec=-1
		if [ "$ec" -ne 0 ]; then
			echo "claude: sandbox-exec exitCode=$ec (want 0): $resp" >&2
			exit 41
		fi
		;;
	"SCRIPT:sandbox-exec-expect-fail "*)
		rest="${line#SCRIPT:sandbox-exec-expect-fail }"
		runtime="${rest%% *}"
		cmdline="${rest#* }"
		cmdjson="$(printf '%s' "$cmdline" | awk '{for(i=1;i<=NF;i++){printf "\"%s\"%s",$i,(i<NF?",":"")}}')"
		payload="$(printf '{"runtime":"%s","command":[%s]}' "$runtime" "$cmdjson")"
		resp="$(curl -sS --max-time 30 -X POST "$SIDECAR/v1/exec" -H 'Content-Type: application/json' -d "$payload")"
		rc=$?
		if [ "$rc" -ne 0 ]; then
			echo "claude: sandbox-exec-expect-fail curl failed (rc=$rc)" >&2
			exit 42
		fi
		ec="$(printf '%s' "$resp" | sed -n 's/.*"exitCode":\(-\?[0-9]\+\).*/\1/p')"
		[ -n "$ec" ] || ec=-1
		# Expect the command to FAIL (exitCode != 0). A 0 means egress was NOT
		# blocked -- the property under test is violated.
		if [ "$ec" -eq 0 ]; then
			echo "claude: sandbox-exec-expect-fail exitCode=0 (want non-zero): $resp" >&2
			exit 42
		fi
		;;
```

```go
// applyServices writes servicesYAML into the env's sidecar container and runs
// `sandboxctl services apply` against it (the real apply CLI path: it reads the
// file and upserts the ServiceSet named after the env). Fails the spec on a
// non-zero CLI exit. The sidecar container holds the sandboxctl binary + SA token.
func (h *Harness) applyServices(ctx context.Context, ns, envName, servicesYAML string) {
	podName := render.ChildNames(envName).Pod
	// Write the declaration to a temp file in the sidecar container.
	_, stderr, err := h.Exec(ctx, ns, podName, render.SidecarContainerName, "sh", "-c",
		"cat > /tmp/services.yaml <<'E2E_SERVICES_YAML'\n"+servicesYAML+"\nE2E_SERVICES_YAML")
	gomega.ExpectWithOffset(1, err).NotTo(gomega.HaveOccurred(), "writing services.yaml into sidecar: %s", stderr)
	// Apply. sandboxctl services apply reads the file and upserts the ServiceSet
	// named cfg.Environment (= envName) in cfg.Namespace.
	stdout, stderr, err := h.Exec(ctx, ns, podName, render.SidecarContainerName,
		"/sandboxctl", "services", "apply", "/tmp/services.yaml")
	gomega.ExpectWithOffset(1, err).NotTo(gomega.HaveOccurred(),
		"sandboxctl services apply failed: stdout=%q stderr=%q", stdout, stderr)
}

// brokerURL is the in-cluster platform-doubles broker -- the egress target for
// the isolation specs (Restricted egress blocks it, Open egress allows it).

	return fmt.Sprintf("http://platform-doubles.%s.svc.cluster.local:8080", h.Cfg.ServicesNamespace)
```

```go
	// approach's "DEFAULT-network container denied the pod loopback" property;
	// under k8s-native it is true by pod separation, asserted end-to-end here.
	It("does not expose the control API to other pods", func() {
		class := h.CreateClass(ctx, WithEngine(sandboxv1alpha1.EngineTypeK8sNative))
		// Keep the env Running and declare a runtime to get a separate pod.
		env := h.CreateEnvironment(ctx, ns, class.Name,
			WithScript("SCRIPT:sleep 600"),
			// Apply the runtime from the agent side so it exists for the test.
			// The fake CLI runs in the agent container; the apply hits the sidecar.
		)
		key := client.ObjectKey{Namespace: ns, Name: env.Name}
		h.WaitForPhase(ctx, key, sandboxv1alpha1.PhaseRunning, h.Cfg.PhaseTimeout)

		// Apply a runtime named "probe" (alpine:3) so a separate pod exists.
		h.applyServices(ctx, ns, env.Name, `
runtimes:
  - name: probe
    image: alpine:3
    command: ["sleep", "infinity"]
`)
		// Wait for the probe pod to be running.
		gomega.Eventually(func() corev1.PodPhase {
			var pod corev1.Pod
			if err := h.Client.Get(ctx, client.ObjectKey{Name: "probe", Namespace: ns}, &pod); err != nil {
				return ""
			}
			return pod.Status.Phase
		}, h.Cfg.PodTimeout, h.Cfg.Poll).Should(gomega.Equal(corev1.PodRunning), "probe runtime pod never Running")

		// The agent pod's IP: the control API is loopback-bound, so reaching it
		// from the probe pod via the agent pod's IP must FAIL.
		agentPod := h.GetAgentPod(ctx, key)
		agentIP := agentPod.Status.PodIP
		gomega.Expect(agentIP).NotTo(gomega.BeEmpty(), "agent pod has no IP")

		_, _, err := h.Exec(ctx, ns, "probe", "probe", "nc", "-z", "-w", "5", agentIP, "9099")
		gomega.Expect(err).To(gomega.HaveOccurred(),
			"runtime pod reached the agent control API at %s:9099 -- it is not loopback-isolated", agentIP)

		// Sanity: the control API IS reachable from the agent's OWN container
		// (loopback), proving it is up, not just absent.
		_, stderr, err := h.Exec(ctx, ns, render.ChildNames(env.Name).Pod, render.AgentContainerName,
			"curl", "-fsS", "--max-time", "5", "http://localhost:9099/healthz")
		gomega.Expect(err).NotTo(gomega.HaveOccurred(),
			"agent container could not reach its own control API on loopback: %s", stderr)
	})
```
